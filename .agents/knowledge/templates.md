# Template authoring

Read when adding, changing, documenting, or publishing a template. `devcontainer-template.json` owns
template identity, options, and version; OpenSpec owns changed behavior; NOTES owns additional user
guidance.

Use `src/<id>/devcontainer-template.json` and `src/<id>/.devcontainer/` for published content. Keep
repository tooling in the root development container. Put executable acceptance assertions in
`test/<id>/test.sh`. IDs are lowercase hyphenated names; retain existing IDs because consumers use
them as registry paths.

Template versions advance independently using SemVer. Every published-content change increments its
template's version; use a new patch release to repair a published version. The public reference is
`ghcr.io/hoshiori-dev/devcontainer-templates/<id>:<version>` and the corresponding source tag is
`<id>/v<version>`. Never move a published source tag. OCI version tags can be changed by package
writers; verify content and provenance, and use `@sha256:<digest>` when a fixed artifact is
required.

Use official images and Features; verify current tags and architecture support before selecting or
updating them. Keep option names and substitutions compatible with the template specification. Every
new option needs a documented default, application coverage, and a version decision. Avoid adding
unused tools or options.

`README.md` files and root template indexes are generated by `just docs` from metadata and NOTES.
Edit those inputs, regenerate, and run `just docs-check`. Hand-written root introduction and usage
instructions are maintained in both English and Chinese. Ubuntu's behavior contract is maintained in
`openspec/specs/ubuntu-template/spec.md`.

When changing packaging or substitutions, consult the authoritative
[template format](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-templates.md)
and
[distribution format](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-templates-distribution.md).
When changing container properties, consult the
[container reference](https://github.com/devcontainers/spec/blob/main/docs/specs/devcontainer-reference.md).
These upstream documents define compatibility; examples in other repositories are implementation
references, not replacements for those contracts.
